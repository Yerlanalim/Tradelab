# План рефакторинга TradeLab Unified Bot (GPT-5 Native)

## Цель
- Перевести поиск поставщиков (Product 3) на нативную архитектуру GPT-5.
- Устранить технический долг, блокировки WAF и проблемы качества данных.
- Ключевое изменение: полный отказ от legacy-параметров и фоллбэков на слабые модели. Работаем строго по спецификации новых моделей (Reasoning/O-series).

---

## I. Архитектурная концепция
- Упрощенная мультиагентная система внутри одной Edge Function (`chat_handler`) для соблюдения ограничений Supabase и скорости.
- **Оркестратор (Main Handler):**
  - Единая точка входа.
  - Маршрутизирует запросы на основе контекста страницы (`mode`).
- **Специализированные Агенты (внутренняя логика):**
  - **Linguist Agent:** перевод запросов (RU ↔ EN/ZH) и локализация ответов.
  - **Search Agent (P3):** исполнитель поиска, валидатор ссылок и парсер данных.
  - **Finance Agent:** контроллер транзакций Trade Credits (списание/возврат).
  - **Assistant Agent:** базовый консультант (HS-коды, калькулятор).

---

## II. Этапы реализации

### Этап 1: Чистый GPT-5 Клиент (Foundation)
- **Задача:** создать API-клиент, строго соответствующий спецификации GPT-5.
- **Особенности:**
  - Полностью удалить передачу параметров `temperature`, `max_tokens`, `top_p`, `frequency_penalty`.
  - В payload остаются только: `model`, `messages` и `tools` (если поддерживаются моделью для веб-поиска).
  - **No-Fallback Policy:** убрать логику переключения на `gpt-4o-mini` при ошибках.
  - Внедрить стратегию `"Fail Fast & Refund"`: при недоступности или перегрузке GPT-5 — возвращать понятную ошибку, сохранять деньги пользователя, а не выдавать некачественный результат.

### Этап 2: Ядро поиска и мультиязычность (Core Logic)
- **Задача:** обеспечить нахождение реальных товаров и правильный перевод.
- **Логика:**
  - **Лингвистический слой (Query Expansion):**
    - препроцессинг: запрос пользователя (RU) → профессиональные термины (EN + ZH).
  - **Два одновременно активных поиска:**
    - `site:alibaba.com` (используются английские термины).
    - `site:made-in-china.com` (используются китайские/английские термины).
  - **WAF-Bypass Валидация:**
    - отказ от HTTP fetch (Alibaba блокирует).
  - **Regex-валидация адресов:**
    - поддерживаемые URL фильтры: `/product-detail/`, `/showroom/`.
    - запрещенные URL: `/search/`, login и другие.
  - **Advanced Parsing (JSON Repair):**
    - механизм восстановления валидного JSON из ответа GPT, даже если он содержит лишний текст.
  - **Обогащение данных:**
    - извлечение `brand`, `supplier_type` (Factory/Trading), `img_url`.

### Этап 3: Оркестрация и безопасность (Safety)
- **Задачи:**
  - Защитить деньги и избегать ошибок переходов.
  - Вести строгий режим работы (Enforcement).
- **Механизмы:**
  - **Strict Mode:**
    - блокировка платных функций в бесплатном режиме.
    - вызов `supplier_search_full` (500 TC) — запрещен в режиме Assistant.
  - **Transactional Integrity:**
    - списание средств → запрос → возврат при ошибке.
  - **Гарантии:**
    - при ошибках модели или тайм-ауте — мгновенный возврат 500 TC с уведомлением.
  - **Localization Enforcement:**
    - финальный системный промпт, который требует обязательный перевод всех технических условий на русский язык перед ответом.

## III. Стратегия тестирования
- Проводится в среде **Preview Deployment** (Supabase Edge Functions).

### Тест-кейсы
1. **Smoke Test (Preview):**  
   - Запрос "Ричстакеры" → бот выдает 3-5 карточек, ссылки на Alibaba/MIC, ответ — на русском.

2. **API Compliance:**  
   - Проверка логов на отсутствие параметра `temperature`.
   - Без ошибок 400 Bad Request.

3. **Money Test (Full):**  
   - Подтверждение — списание 500 TC — отчет из 10 позиций с рисковыми статусами.

4. **Failover & Refund:**  
   - Искусственно вызываем ошибку или мусор — бот говорит "Не удалось сформировать отчет" — деньги возвращаются в `tc_ledger`.

## IV. Что получим в итоге (Definition of Done)
- **Качество данных:** ≥ 90% валидных, кликабельных ссылок.
- **Мультиязычность:** бот понимает русский, ищет на английском/китайском, отвечает по-русски.
- **Стабильность:** отсутствие ошибок API из-за параметров.
- **Честный биллинг:** плату списываем только за успешный результат.
- **Чистый код:** единственный TypeScript-файл с изолированной логикой клиента GPT-5.
