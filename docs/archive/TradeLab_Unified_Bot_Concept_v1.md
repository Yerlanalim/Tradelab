## 3. Новый бот: TradeLab Assistant

### 3.1. Общее описание

**TradeLab Assistant** — единый AI-ассистент платформы, который:
- Присутствует на всех страницах в едином интерфейсе чата
- Автоматически адаптируется к контексту текущей страницы
- Работает в разных **режимах** в зависимости от страницы
- Сохраняет историю и контекст между сессиями
- Умеет выполнять все функции старых ботов через единую точку входа

### 3.2. Принцип работы

```
Пользователь открывает любую страницу
         ↓
Определяется РЕЖИМ бота (Assistant / Supplier Search / Report)
         ↓
Чат-панель в соответствующем UI
         ↓
Бот получает контекст: page_context + mode + user_state + chat_history
         ↓
Динамически формируется system prompt с учётом режима
         ↓
Бот отвечает с учётом контекста и ограничений режима
         ↓
При необходимости вызывает tools (web search, расчёты, API)
         ↓
Результат сохраняется в единую историю с metadata
```

### 3.3. Контексты страниц

Бот понимает, на какой странице находится пользователь, и работает в соответствующем режиме:

| Страница | page_context | Режим | Фокус бота |
|----------|--------------|-------|------------|
| Главная | `/dashboard` | Assistant | Навигация, онбординг, общие вопросы |
| Карта Китая | `/map` | Assistant | Информация о регионах, навигация |
| Библиотека | `/library` | Assistant | Навигация по материалам |
| Калькулятор | `/calculator` | Assistant | Расчёты landed cost |
| Мои отчёты | `/reports` | Assistant | Помощь с отчётами, интерпретация |
| **Поиск поставщиков** | `/products/supplier-search` | **Supplier Search** | **Полный flow поиска (платный сервис)** |
| Проверка компании | `/products/company-check` | Report | Помощь с P1, интерпретация справки |
| Экспортный профиль | `/products/export-profile` | Report | Помощь с P2, анализ экспорта |
| Анализ рынка | `/products/market-analysis` | Report | Помощь с P4, интерпретация данных |

### 3.4. Возможности бота (Tools)

Бот должен уметь вызывать следующие инструменты через function calling:

**Поиск и анализ:**

| Tool | Описание | Доступен в режимах | Результат |
|------|----------|-------------------|-----------|
| `supplier_search_full` | Полный поиск поставщиков | Только Supplier Search | 10 поставщиков + скорринг |
| `supplier_search_preview` | Preview поиска (3 примера) | Supplier Search | 3 примера для ориентира |
| `supplier_tips` | Советы по поиску (без поиска) | Assistant | Рекомендации, на что обратить внимание |
| `hs_classify` | Определение HS-кода товара | Все режимы | HS-код + альтернативы |
| `company_lookup` | Поиск информации о компании | Все режимы | Базовая информация |

**Расчёты:**

| Tool | Описание | Доступен в режимах | Результат |
|------|----------|-------------------|-----------|
| `landed_cost_calc` | Расчёт полной стоимости импорта | Все режимы | Пошлина, НДС, доставка, итого |
| `duty_calc` | Расчёт только пошлин | Все режимы | Ставка пошлины, сумма |

**Оценка и анализ:**

| Tool | Описание | Доступен в режимах | Результат |
|------|----------|-------------------|-----------|
| `risk_assessment` | Оценка рисков сделки | Все режимы | Карта рисков, светофор |
| `report_interpret` | Интерпретация отчёта | Report, Assistant | Пояснения, выводы |

**Системные:**

| Tool | Описание | Когда вызывается |
|------|----------|------------------|
| `check_balance` | Проверка баланса TC | Перед платными операциями |
| `deduct_credits` | Списание TC | После подтверждения пользователем |
| `create_report` | Генерация отчёта | После завершения платного запроса |

### 3.5. Чипы (Quick Actions)

Чипы — это кнопки быстрого доступа к функциям, которые отображаются над полем ввода.

**Чипы в режиме Assistant:**
- `[📦 HS-код]`
- `[💰 Расчёт стоимости]`
- `[⚠️ Оценка рисков]`
- `[🔍 Найти поставщиков]` → **редирект на страницу Supplier Search**

**Чипы в режиме Supplier Search:**
- `[🔄 Новый поиск]`
- `[📦 Уточнить HS-код]`
- `[📊 Сравнить результаты]`
- `[✅ Оформить полный отчёт]`

**Чипы в режиме Report (страницы P1, P2, P4):**
- `[❓ Объясни этот раздел]`
- `[📋 Что означает статус]`
- `[➡️ Что делать дальше]`

**Важно:** В режиме Assistant чип "Найти поставщиков" НЕ запускает поиск, а перенаправляет пользователя на страницу `/products/supplier-search`.

#### Flow: Определение HS-кода (все режимы)

```
1. Триггер: чип или вопрос о классификации
2. Бот запрашивает описание товара
3. Использует web search для поиска аналогов и классификации
4. Возвращает:
   - Основной HS-код (6-8 цифр)
   - 2-3 альтернативных варианта
   - Ставку пошлины для KZ
   - Рекомендацию проверить в таможне
5. В режиме Assistant: "Хотите найти поставщиков этого товара? 
   [Перейти к поиску]"
6. В режиме Supplier Search: "Использовать этот HS-код для поиска? 
   [Да, искать]"
```

---

#### Flow: Расчёт Landed Cost (все режимы)

```
1. Триггер: чип или вопрос о стоимости
2. Бот собирает данные:
   - HS-код (или определяет через hs_classify)
   - Стоимость FOB (USD)
   - Вес брутто (кг)
   - Условия поставки
3. Рассчитывает:
   - Таможенная стоимость
   - Пошлина (по ставке HS)
   - НДС 12%
   - Ориентир по доставке
4. Выводит итоговую таблицу
5. Дисклеймер: "Точный расчёт зависит от условий — 
   рекомендуем консультацию таможенного брокера"
```

---

#### Flow: Оценка рисков сделки (все режимы)

```
1. Триггер: чип или вопрос о рисках
2. Бот задаёт 5-7 вопросов (Quick Reply кнопки):
   - Как давно знаете поставщика?
   - Есть ли верификация на платформе?
   - Условия оплаты?
   - Была ли видеоинспекция/визит?
   - Размер первого заказа?
   - Есть ли контракт?
3. На основе ответов генерирует:
   - Карту рисков (светофор по категориям)
   - Общий уровень риска
   - Конкретные рекомендации по митигации
4. Апсейл: "Хотите проверить компанию через госреестр КНР?" → 
   Переход на страницу Продукта 1
```

## 4. Режимы работы бота

### 4.1. Обзор режимов

| Режим | Где активен | Назначение | Ментальная модель |
|-------|-------------|------------|-------------------|
| **Assistant** | Dashboard, карта, библиотека, калькулятор, отчёты | Бесплатный помощник | "Консультант в магазине" |
| **Supplier Search** | Только `/products/supplier-search` | Платный сервис поиска | "Специалист по подбору" |
| **Report** | Страницы P1, P2, P4 | Помощь с платными отчётами | "Аналитик по отчёту" |

### 4.2. Режим Assistant (по умолчанию)

**Страницы:** `/dashboard`, `/map`, `/library`, `/calculator`, `/reports`

**Поведение:**
- Отвечает на общие вопросы об импорте из Китая
- Помогает с навигацией по платформе
- Выполняет бесплатные расчёты (landed cost, HS-код, риски)
- **НЕ выполняет полный поиск поставщиков**
- При запросе поиска — направляет на страницу Supplier Search

**Ограничения:**
- Может дать 2-3 общих примера поставщиков "для ориентира"
- НЕ использует tool `supplier_search_full`
- НЕ предлагает оплату за поиск напрямую

**Пример поведения:**

```
Пользователь: "Найди производителя пластиковых контейнеров"

❌ НЕПРАВИЛЬНО (бот НЕ должен так делать):
"Вот 10 поставщиков... Хотите полный отчёт за 500 TC?"

✅ ПРАВИЛЬНО:
"Пластиковые контейнеры — широкая категория. 

Основные регионы производства:
• Чжэцзян (Тайчжоу) — крупнейший кластер
• Гуандун — ближе к портам

На что обратить внимание:
• Сертификация (пищевой пластик требует FDA/LFGB)
• MOQ обычно от 5,000 шт
• Тип формовки (injection/blow molding)

Для подбора конкретных поставщиков с анализом — 
перейдите в раздел Поиск поставщиков.

[🔍 Перейти к поиску]"
```

### 4.3. Режим Supplier Search

**Страница:** только `/products/supplier-search`

**Поведение:**
- Бот работает как **платный сервис**
- Ведёт пользователя через guided flow
- Собирает параметры поиска
- Показывает бесплатный preview
- Предлагает полный отчёт за 500 TC
- После оплаты — генерирует полный отчёт

**Особенности:**
- Другой UI (бот в центре страницы, не в сайдбаре)
- Прогресс-бар сверху (этапы поиска)
- Нет отвлекающего контента
- Чёткий flow от запроса до оплаты

**Доступные tools:**
- `supplier_search_preview` — бесплатно
- `supplier_search_full` — 500 TC
- `hs_classify` — бесплатно (помощь с параметрами)

### 4.4. Режим Report

**Страницы:** `/products/company-check`, `/products/export-profile`, `/products/market-analysis`

**Поведение:**
- Помогает пользователю с конкретным продуктом
- Объясняет, что включено в отчёт
- Помогает заполнить форму (USCC, название компании, HS-код)
- После генерации отчёта — помогает интерпретировать
- Предлагает связанные продукты (апсейл)

**Особенности:**
- Бот знает контекст продукта (P1/P2/P4)
- Может отвечать на вопросы о сгенерированном отчёте
- Предлагает следующие шаги

**Пример поведения на странице P1:**

```
Пользователь: "Что такое USCC?"

Бот: "USCC (Unified Social Credit Code) — это 18-значный 
уникальный идентификатор китайской компании, аналог ИИН/БИН.

Где найти:
• В бизнес-лицензии поставщика (营业执照)
• На сертификатах и договорах
• Запросить напрямую у поставщика

Формат: 91440300MA5EQXXX0X

Введите USCC в поле выше, и я сформирую справку о компании."
```

## 5. Система памяти

### 5.1. Уровни памяти

**Уровень 1: Контекст сообщения (immediate)**
- Текущее сообщение пользователя
- Контекст страницы (page_context)
- Текущий режим бота (mode)
- Данные на экране (если релевантно)

**Уровень 2: Контекст сессии (session)**
- История текущего диалога (последние N сообщений)
- Собранные параметры (товар, MOQ, бюджет)
- Результаты предыдущих запросов в этой сессии
- Текущий этап flow (для Supplier Search)

**Уровень 3: Контекст пользователя (user)**
- История всех диалогов пользователя
- Сохранённые поставщики и компании
- Предпочтения (категории, регионы)
- Сгенерированные отчёты

### 5.2. Структура хранения

**Таблица: chat_sessions**

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Первичный ключ |
| user_id | UUID | Ссылка на пользователя |
| mode | text | Режим сессии (assistant/supplier_search/report) |
| started_at | timestamp | Начало сессии |
| ended_at | timestamp | Конец сессии (null = активна) |
| page_contexts | text[] | Страницы, посещённые в сессии |
| flow_state | jsonb | Состояние flow (для Supplier Search) |
| summary | text | AI-generated краткое содержание |

**Таблица: chat_messages**

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID | Первичный ключ |
| session_id | UUID | Ссылка на сессию |

### 5.4. Как бот использует память

**При новом сообщении:**

1. Загрузить последние N сообщений текущей сессии
2. Загрузить entities пользователя (для персонализации)
3. Проверить, есть ли незавершённые flows
4. Определить режим по page_context
5. Сформировать контекст для LLM

**Пример использования cross-session памяти:**

```
Сессия 1 (режим Supplier Search):
User: "Ищу поставщика LED-панелей 600x600"
Bot: [нашёл 10 поставщиков, сохранил в отчёт]
→ Сохранено: product="LED panels 600x600", suppliers=[...]

Сессия 2 (режим Report, страница P1):
User: "Проверь компанию Shenzhen Lighting"
Bot: [видит в entities, что это один из найденных поставщиков]
     "Shenzhen Lighting Co. — это один из поставщиков LED-панелей 
     из вашего недавнего поиска. 
     
     Для справки нужен USCC. Он есть в вашем отчёте:
     91440300MA5EQXXX0X
     
     Использовать этот USCC? [Да] [Ввести другой]"
```

### 5.5. Границы памяти

**Что помним:**
- Последние 100 сообщений в деталях
- Все извлечённые entities (без срока давности)
- Все сгенерированные отчёты
- Preferences пользователя

**Что НЕ храним:**
- Полный текст tool_results (только summary)
- Промежуточные данные расчётов
- Черновики незавершённых отчётов

**Политика очистки:**
- Сессии старше 90 дней — архивировать (только summary)
- Entities без активности 180 дней — помечать inactive
- Удаление по запросу пользователя (GDPR compliance)

## 6. System Prompt Architecture

### 6.1. Структура промпта

System prompt формируется динамически из блоков:

```
[BASE_PROMPT]
+
[MODE_PROMPT]           ← НОВЫЙ БЛОК
+
[PAGE_CONTEXT_PROMPT]
+
[USER_STATE_BLOCK]
+
[AVAILABLE_TOOLS_BLOCK]
+
[MEMORY_CONTEXT_BLOCK]
```

### 6.2. BASE_PROMPT (всегда)

Содержит:
- Роль: "Ты TradeLab Assistant — эксперт по работе с китайскими поставщиками"
- Целевая аудитория: импортёры из СНГ/ЕАЭС
- Тон: профессиональный, но дружелюбный
- Язык: русский (основной), понимает английский и китайский
- Ограничения: не даёт юридических гарантий, дисклеймеры
- Форматирование: использовать emoji-светофоры, структурированные ответы

### 6.3. MODE_PROMPT (по режиму)

**Для режима Assistant:**
```
Ты работаешь в режиме ПОМОЩНИКА.

Твои задачи:
- Отвечать на вопросы об импорте из Китая
- Помогать с расчётами (landed cost, пошлины)
- Определять HS-коды
- Оценивать риски сделок
- Помогать с навигацией по платформе

ВАЖНО: Ты НЕ выполняешь полный поиск поставщиков в этом режиме.
При запросе поиска — направляй пользователя на страницу 
"Поиск поставщиков" через кнопку/ссылку.

Можешь давать общие советы и 2-3 примера для ориентира,
но для полноценного поиска с анализом — нужна страница Supplier Search.
```

**Для режима Supplier Search:**
```
Ты работаешь в режиме ПОИСКА ПОСТАВЩИКОВ.

Это платный сервис (500 TC за полный отчёт).

Твой flow:
1. Собери параметры поиска (товар, спецификации, MOQ, регион)
2. Покажи бесплатный preview (3 примера)
3. Предложи полный отчёт (10 поставщиков) за 500 TC
4. После оплаты — сгенерируй полный отчёт
5. Предложи апсейл (проверка компании через P1/P2)

Используй Quick Reply кнопки для сбора параметров.
Показывай прогресс (этапы поиска).
```

**Для режима Report:**
```
Ты работаешь в режиме ПОМОЩИ С ОТЧЁТОМ.

Текущий продукт: [P1/P2/P4]

Твои задачи:
- Помочь заполнить форму (объяснить поля, валидировать)
- После генерации — помочь интерпретировать отчёт
- Объяснить значение показателей
- Предложить связанные продукты (апсейл)

Знай контекст продукта и его специфику.
```

### 6.4. PAGE_CONTEXT_PROMPT (по странице)

Дополнительный контекст для конкретной страницы:
- Описание страницы
- Специфичные инструкции
- Примеры ответов

### 6.5. USER_STATE_BLOCK

Динамически подставляется:
- Баланс Trade Credits
- Количество отчётов
- Последние действия (если релевантно)
- Язык интерфейса

### 6.6. MEMORY_CONTEXT_BLOCK

Краткое summary из памяти:
- Последние 3-5 сообщений диалога
- Активные entities (если есть)
- Незавершённые flows

## 8. Интеграция с продуктами

### 8.1. Связь бота с платными продуктами

| Действие в боте | Продукт | Стоимость | Где доступно |
|-----------------|---------|-----------|--------------|
| Полный поиск поставщиков | P3 | 500 TC | Только Supplier Search |
| Справка о компании | P1 | 2,000 TC | Report (страница P1) |
| Экспортный профиль | P2 | 2,000 TC | Report (страница P2) |
| Анализ рынка | P4 | 5,000 TC | Report (страница P4) |
| Бандл P1+P2 | Bundle | 3,500 TC | Report (страницы P1/P2) |

### 8.2. Flow оплаты в боте

```
1. Пользователь запрашивает платное действие
2. Бот проверяет баланс TC
3. Если баланса достаточно:
   → Alert: "Сформировать отчёт за X TC? [Да] [Нет]"
4. Если баланса НЕ достаточно:
   → Alert: "Недостаточно TC. Ваш баланс: Y TC. [Пополнить баланс]"
5. При подтверждении:
   → Списание TC
   → Запуск генерации (показать прогресс)
   → "Отчёт готов! [Открыть] [Скачать PDF]"
```

### 8.3. Апсейл логика

**После поиска поставщиков (P3) → в режиме Supplier Search:**
- "Хотите проверить [название] через госреестр? [Перейти к проверке]"
- Кнопка ведёт на страницу P1 с предзаполненными данными

**После справки о компании (P1) → в режиме Report:**
- "Рекомендую также проверить экспортную активность [Заказать P2]"
- "Хотите найти альтернативных поставщиков? [Перейти к поиску]"

**После экспортного профиля (P2) → в режиме Report:**
- "Для понимания рынка закажите Анализ рынка [Заказать P4]"
- "Ищете других поставщиков? [Перейти к поиску]"

## 9. Технические требования

### 9.1. Backend

**Edge Function: chat-handler**
- Единая точка входа для всех сообщений
- Принимает: message, page_context, session_id
- Определяет mode по page_context
- Возвращает: response, tool_calls, suggested_chips, ui_hints

**Логика обработки:**
1. Валидация входных данных
2. Определение режима (mode) по page_context
3. Загрузка контекста (сессия, пользователь, память)
4. Формирование system prompt с учётом режима
5. Вызов LLM (GPT-4o)
6. Проверка ограничений режима (блокировка недоступных tools)
7. Обработка tool calls (если есть и разрешены)
8. Извлечение entities из ответа
9. Сохранение в БД
10. Возврат ответа с ui_hints (для фронтенда)

### 9.2. LLM конфигурация

| Параметр | Значение |
|----------|----------|
| Model | gpt-4o |
| Temperature | 0.7 (диалог), 0.3 (расчёты, поиск) |
| Max tokens | 2048 |
| Tools | web_search + custom functions (фильтруются по режиму) |

### 9.3. Rate Limits и защита

- Максимум 30 сообщений в минуту на пользователя
- Максимум 100 tool calls в час на пользователя
- Защита от инъекций в промпт
- Логирование аномалий
- Проверка режима при каждом tool call (защита от обхода)

## 12. Риски и митигация

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| LLM hallucinations | Средняя | Structured output, fact-checking prompts |
| Высокая latency | Средняя | Streaming responses, оптимизация промптов |
| Обход ограничений режима | Низкая | Серверная проверка mode при каждом tool call |
| Путаница между режимами | Средняя | Чёткие визуальные различия UI, разные заголовки |
| Пользователь не понимает, что поиск платный | Средняя | Preview бесплатно, чёткие цены до оплаты |
| Превышение лимитов OpenAI | Низкая | Мониторинг, fallback на gpt-4o-mini |
