# План 3 — Подключение OpenAI и Apify к продуктам TradeLab

## Короткое резюме текущей стадии (по MCP)
- Supabase: есть таблицы `orders`, `reports`, `report_jobs`, `payments`, `api_usage`,
  `chat_history`, `supplier_entities`, `supplier_matches`, `supplier_features`,
  `content_items`, `user_profiles`. Включен RLS.
- Supabase Edge Functions: опубликованы `ai_orchestrator`, `apify_proxy`.
- Apify: используются акторы
  - `piotrv1001/alibaba-listings-scraper` (параметры `search`, `limit`)
  - `agenscrape/made-in-china-com-product-scraper` (параметры `searchMode`, `keyword`, `maxResults`)

## Цель плана
Подключить OpenAI и Apify так, чтобы продукты P1–P4 работали с реальными данными,
а P3 (поиск поставщиков) в dev-режиме был ограничен лимитами 20/20
для Alibaba и Made-in-China.

---

## Этап 0. Базовая готовность и безопасность
1) Секреты и окружение
   - Проверить, что `OPENAI_API_KEY` и `APIFY_TOKEN` заданы в Supabase secrets.
   - В Vercel оставить только публичные ключи Supabase.
   - Подготовить env флаги для dev/prod (например, `TRADLAB_STAGE=dev`).
2) Логи и лимиты
   - Использовать таблицу `api_usage` для учета вызовов OpenAI/Apify.
   - Зафиксировать лимиты dev-поиска: `limit=20` для Alibaba и `maxResults=20` для MIC.
3) Деплой Edge Functions (Supabase)
   - Убедиться, что `ai_orchestrator` и `apify_proxy` задеплоены.
   - Проверить, что `verify_jwt=true` (доступ только для авторизованных).
4) Контроль доступа
   - Проверить RLS на `orders`, `reports`, `chat_history` и `api_usage`.
   - Убедиться, что клиентский доступ не раскрывает секреты.

## Этап 1. OpenAI (чаты и интеллект)
1) Привести system prompts к единому источнику
   - Сверить `supabase/functions/ai_orchestrator` и `src/lib/ai/prompts.ts`.
   - Зафиксировать формат ответа (структура + короткие выводы).
2) Чат-контексты по разделам
   - Поддержка секций: `p1`, `p2`, `p3`, `p4`, `map`, `library`, `general`.
   - Запись истории в `chat_history` (по `user_id`, `section`).
3) Подключение к продуктам
   - P1: генерация интерпретации справки (green/yellow/red flags).
   - P2: генерация блока “Релевантность к сделке”.
   - P3: генерация RFQ запроса по выбранному товару.
   - P4: генерация Actionable Insights.
4) Деплой Edge Functions
   - Задеплоить обновления `ai_orchestrator` (после правок).

## Этап 2. Apify (P3 — поиск поставщиков)
1) Ограничения dev-режима
   - В `apify_proxy` жестко ограничить `limit/maxResults` до 20
     (для тестов и контроля расходов).
2) Нормализация данных
   - Привести цены, MOQ и локации к единому виду.
   - Выделить поля для `Price/MOQ Bench`.
3) Бенчмарки
   - Рассчитать min/median/max по цене и MOQ, отдавать в UI.
4) Кеширование и Supplier ID
   - Сохранять `supplier_entities` + `supplier_matches` (source=apify).
   - Дедупликация по url/названию/локации.
5) Деплой Edge Functions
   - Задеплоить обновления `apify_proxy` (после правок).

## Этап 3. Связка с таблицами заказов/отчетов
1) `orders` и `reports`
   - На запуск продукта создавать `orders` со статусом `processing`.
   - Формировать `reports` с `params`, `result_summary`, `pdf_url`.
2) `report_jobs`
   - Очередь для генерации PDF и тяжелых вызовов.
3) `api_usage`
   - Логировать вызовы OpenAI/Apify с `cost_estimate`.
4) Проверка RLS
   - Подтвердить, что доступ к заказам и отчетам ограничен `user_id`.

## Этап 4. Генерация отчетов (PDF + web report)
1) Реализовать `report_generator`:
   - P1/P2/P4: PDF (React-PDF) + краткое резюме.
   - P3: web-отчет + экспорт.
2) Хранение
   - `pdf_url` в Supabase Storage или внешнем бакете.
   - `web_report_url` для P3/P4.
3) Деплой
   - Задеплоить `report_generator`.

## Этап 5. UI и валидации
1) Conversational Form
   - Заменить заглушки на реальные поля.
   - Валидации: USCC, HS-код, keyword/attributes.
2) Ошибки и UX
   - Показ статуса `processing/ready/failed`.
   - Ретраи и безопасные сообщения.

## Этап 6. Тестирование и контроль расходов
1) Dev-прогоны:
   - P3 с лимитом 20/20.
   - Пробные чаты и генерации.
2) Метрики:
   - В `api_usage` контролировать себестоимость.
3) Готовность к прод:
   - Перевести лимиты на конфиг среды (dev/prod).
   - Проверить мониторинг ошибок (Sentry).

## Этап 7. Безопасность и корректность API
1) Защита `/api/reports/generate`
   - Проверка авторизации и сверка `userId`.
   - Запрет генерации PDF без валидного токена.
2) Проверка storage bucket
   - Убедиться, что политики Storage ограничивают доступ по `user_id`.
3) Конфигурация окружений
   - Закрепить `TRADLAB_STAGE=DEV` в Supabase secrets.

## Этап 8. Полный жизненный цикл отчетов
1) Единый сервис генерации отчетов
   - Вынести логику из страниц P1/P2/P4 в общий сервис.
2) Подключить `report_jobs`
   - Запись задач, ретраи, статусные ошибки.
3) Обновление статусов
   - `orders` → `processing/done/failed`, `reports` → `processing/ready/failed`.

## Этап 9. Улучшение PDF и “evidence-first”
1) Обогащение PDF
   - Блоки “Источник” и “Ограничение”.
2) Единый шаблон секций
   - Сводка, параметры, ключевые выводы.

## Этап 10. Полировка UX
1) “Мои отчёты”
   - Показ наличия PDF и быстрая ссылка.
2) Карточка отчета
   - Показ статуса, параметров и кнопок действий.
3) Ошибки
   - Четкие сообщения о причинах (данные/лимиты/сеть).

## Этап 11. Мониторинг и себестоимость
1) Стоимость OpenAI/Apify
   - Заполнять `cost_estimate` и агрегировать метрики.
2) Алёрты
   - Sentry + базовые алёрты на сбои.
