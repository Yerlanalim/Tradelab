Структура полноценного агента по международной торговле, рассчитанная на то, что у вас уже есть:
CMS-список HS-кодов,
источники данных по тарифам/налогам,
данные для калькуляции доставки.

1. Роль агента (формулировка без маркетинга)
Агент TradeLab — это оркестратор знаний, расчётов и процедур,
который сопровождает сделку международной торговли
от описания товара до растаможки и доставки,
с трассируемыми решениями и управляемыми рисками.
Ключевое:
он не “знает всё”, он знает — что проверить, что рассчитать и когда эскалировать человеку.

3. Agent Brain — ядро (самое важное)3.1 State Machine (обязательная)
Агент всегда находится в одном состоянии:
INTAKE
Сбор и нормализация данных о товаре и сделке
CLASSIFICATION
Подбор HS-кодов и проверка рисков
CALCULATION
Пошлины / налоги / логистика
COMPLIANCE CHECK
Документы, ограничения, сертификация
ASSEMBLY
Сбор итогового пакета
ESCALATION / CONFIRMATION
Где нужен человек (брокер, логист)
👉 Это защищает от “галлюцинирующего консультанта”.
3.2 Политики (guardrails)
Жёсткие правила, прошитые в агенте:
❌ Запрещено утверждать HS-код как финальный без confidence ≥ X или human approval
❌ Запрещено выдавать точную сумму пошлины без подтверждённых ставок
❌ Запрещено пропускать intake-поля, критичные для расчёта
✅ Обязательно показывать assumptions
✅ Обязательно указывать источники (ID документа / CMS-запись)

  "destination_city": ""

Ключевая идея:
HS-код — это функция + материал + назначение, а не просто “название товара”.
5. HS Engine (на базе вашей CMS)5.1 Вход → выход
Вход: паспорт товара
Выход:
{
  "candidates": [
    {
      "hs_code": "xxxx.xx",
      "confidence": 0.72,
      "rationale": ["material", "function", "precedent_case_id"],
      "risk_flags": ["possible reclassification"]
    }
  ],
  "requires_human_confirmation": true
}
5.2 Как агент использует HS
если confidence высокий → можно идти дальше;
если низкий → задаёт уточняющие вопросы;
если есть риск → заранее предупреждает о корректировке стоимости/кода.
Это ровно то, за что платят энтерпрайз-клиенты.
6. Calculation Layer6.1 Duty & VAT Calculator
Использует:
HS-код (или кандидаты),
режим (импорт),
страну,
стоимость,
курс,
налоговую модель РК.
Выход всегда диапазон, если нет 100% уверенности.
{
  "customs_duty": {
    "range": [8, 12],
    "note": "depends on final HS confirmation"
  },
  "vat": {
    "rate": 12,
    "base": "CIF + duty"
  }
}

7. Compliance & Documents Engine7.1 Генератор требований
На основе:
HS,
назначения товара,
страны,
типа клиента (B2B/B2C).
Выдаёт:
обязательные документы,
условные документы,
стоп-факторы.
{
  "mandatory": ["invoice", "packing list", "contract"],
  "conditional": ["certificate of conformity"],
  "red_flags": ["missing labeling in CN"]
}
7.2 Документный пайплайн
Агент не только перечисляет, но и:
генерирует шаблоны,
проверяет загруженные файлы,
валидирует поля (вес ≠ объём ≠ инвойс).
8. Memory Layer — эффект «самообучения»8.1 Что хранится
Case memory
– что сработало / где была ошибка
Playbooks
– типовые сценарии (“электроника CN→KZ DAP”)
Client profile
– любимые маршруты, брокеры, товары
8.2 Что НЕ хранится
“обобщённые знания” без источников;
решения без подтверждения outcome.
9. Итоговый формат ответа агентa (стандарт)
Каждый ответ — строго структурирован:
Резюме решения
Что принято как допущение
HS-классификация (с уверенностью)
Смета (пошлины / логистика)
Документы и шаги
Риски и точки контроля
Что нужно от клиента / брокера
10. Почему это действительно «полноценный ассистент»
Потому что он:
не выдаёт “магических ответов”;
снижает количество ошибок до подачи;
экономит время брокера и клиента;
масштабируется на новые страны и коридоры;
юридически и операционно безопасен.
