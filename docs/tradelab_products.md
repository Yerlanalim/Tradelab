## 0) Принципы v2.1 (что изменено относительно v2.0)

### 0.1. От «отчётов» к «решениям»
Каждый продукт отвечает на управленческий вопрос импортёра, а не просто выдаёт данные:
- **Можно ли доверять контрагенту юридически?**
- **Есть ли релевантный экспорт под мою сделку?**
- **Кого из поставщиков стоит проверять в первую очередь?**
- **Кто реально возит этот товар в Казахстан и по каким диапазонам цен/объёмов?**

### 0.2. “Evidence-first + Human-in-the-loop”
LLM используется как интерфейс и интерпретатор, но не как «арбитр истины»:
- данные показываются явно;
- выводы сопровождаются пояснением факторов;
- при низкой уверенности — запрос подтверждения пользователя.

### 0.3. Data-layer накапливается из оплаченных действий
Система аккумулирует **обезличенные признаки и агрегаты**, а не «сырые записи», чтобы:
- снижать себестоимость;
- ускорять выдачу;
- сохранять юридическую чистоту и доверие клиентов.

## 2) Общий workflow (снижение когнитивной нагрузки через AI-диалог)

Перед запуском любого платного отчёта пользователь проходит короткий «чат-опрос» (Conversational Form):

1) **Уточнение запроса**
- товар и ключевые атрибуты (материал, размер, назначение, стандарты)
- рынок назначения (KZ / ЕАЭС / СНГ)
- бюджет/целевой диапазон (опционально)

2) **Подбор HS-кода и терминов (RU → EN/ZH)**
- система предлагает **HS-код + альтернативы + уверенность**
- пользователь подтверждает (или корректирует)

3) **Запуск продукта**
- только после подтверждения параметров система расходует лимиты API и формирует отчёт.

> Цель: выглядеть современно и удобно, но минимизировать «фантазирование» ИИ и ошибки классификации.

## 3) Продукт 1: Справка о компании + Интерпретация

### 3.1. Суть продукта
Официальная справка о китайской компании на основе данных госреестра КНР.  
Подтверждает юридическое существование, тип компании, структуру, адрес, юридическую историю.

### 3.2. Входные данные
**Unified Social Credit Code (USCC) — 18 символов**, например: `91440300MA5EQXXX0X`

> ✅ USCC предпочтительнее названия компании: почти исключает ошибочную идентификацию.

### 3.3. Что включено в отчёт (данные)
| Раздел | Данные |
|---|---|
| Регистрация | Название (中文/EN), дата регистрации, статус (Active/Inactive) |
| Тип компании | Производитель / Торговая / Смешанная |
| Капитализация | Уставный капитал, изменения |
| Руководство | Законный представитель, ключевые лица |
| Акционеры | Учредители, доли |
| Business scope | На китайском + перевод |
| Адрес | Юр.адрес, тип локации (промзона/жилой район — если доступно) |
| Контакты | Телефон/email (если доступны) |
| Юр.история | Судебные дела, чёрные списки, нарушения (по доступным данным) |

### 3.4. Что включено в отчёт (интерпретация для импортёра) — **новое**
Добавляется 1 страница “Как читать справку (для импортёра)”, автоматически сформированная TradeLab:
- **Green flags:** признаки устойчивости (статус, срок существования, стабильный scope)
- **Yellow flags:** типовые зоны уточнения (слишком широкий scope, частые изменения)
- **Red flags:** сильные риски (inactive/abnormal, множественные судебные события и пр.)
- **Рекомендованные вопросы поставщику:** 5–7 коротких вопросов по выявленным рискам

> Это повышает ценность для МСБ, не превращая отчёт в юридическое заключение.

### 3.5. Формат выдачи
**PDF, 2-3 страницы:**
- бренд TradeLab
- QR-код для проверки подлинности (идентификатор отчёта, дата)
- дисклеймер

### 3.6. Цена и экономика
- Цена: **$20**
- Себестоимость (QCC): **$3–5** (требуется перпроверка)
- Маржа: **75–85%**

### 3.7. Пакеты
| Пакет | Цена | Экономия |
|---|---:|---:|
| 3 справки | $50 | 17% |
| 5 справок | $80 | 20% |
| 10 справок | $150 | 25% |

### 3.8. Источник данных
**QCC (Qichacha) Singapore API**, синхронизация с GSXT.

## 4) Продукт 2: Экспортный профиль + Релевантность к сделке

### 4.1. Суть продукта
Аналитический отчёт об экспортной активности компании за последний год (12 месяцев).  
Показывает не только “экспорт есть/нет”, но и **насколько он релевантен вашей сделке**.

### 4.2. Входные данные
- Название компании (EN или 中文)  
- ИЛИ USCC (предпочтительно)

### 4.3. Что включено в отчёт (данные)
| Раздел | Данные |
|---|---|
| Факт экспорта | Подтверждение активности |
| Период | Первая/последняя отгрузка |
| Объёмы | Общий объём USD (оценка) |
| География | Топ-10 стран |
| Экспорт в СНГ/ЕАЭС | KZ/RU/UZ/KG и др. — отдельным блоком |
| HS-коды | HS-направления экспорта |
| Динамика | График по месяцам, тренд |
| Частота | Среднее отгрузок/месяц |
| Регулярность | сезонность/стабильность |

### 4.4. Блок “Релевантность к вашей сделке” — **новое**
TradeLab добавляет оценку применимости данных под конкретный кейс пользователя:

**(A) HS match**
- ✅ совпадает / ⚠ частично / ❌ не совпадает  
- список “top HS” компании vs выбранный HS пользователя

**(B) Масштаб vs ваша потребность**
- ориентир по “типовой величине поставок” (диапазон)  
- комментарий: “поставки сопоставимы/ниже/выше”

**(C) Стабильность**
- регулярность (частота)  
- аномалии (однократные пики vs стабильные поставки)

**(D) Региональная пригодность**
- наличие поставок именно в СНГ как фактор логистической “привычки” к региону

> Важно: это не «вердикт», а структурированная интерпретация признаков.

### 4.5. Формат выдачи
**PDF, 3–4 страницы:**
- графики и диаграммы
- визуально выделенный блок “СНГ/ЕАЭС”
- отдельный блок “Релевантность к сделке”

### 4.6. Цена и экономика
- Цена: **$20**
- Себестоимость (Tendata): **$3–5** (требует проверки)
- Маржа: **75–85%**

### 4.7. Источник данных
**Tendata API** (задержка данных 1–3 месяца).

## 5) Продукт 3: Поиск поставщиков (20–30, но релевантных) + Price/MOQ Bench

### 5.1. Суть продукта
Мультиплатформенный автоматизированный поиск поставщиков под заданный запрос.  
Цель — не “много вариантов”, а **короткий список релевантных кандидатов**, удобный для принятия решения и апсейла на проверку.

### 5.2. Процесс использования
Шаг 1: Диалог с AI (товар + атрибуты + HS + бюджет)
Шаг 2: Формирование запросов EN/ZH
Шаг 3: Поиск (Alibaba + Made-in-China)
Шаг 4: Дедупликация + нормализация
Шаг 5: Жёсткая фильтрация → 20–30 релевантных предложений
Шаг 6: Price/MOQ/Lead-time bench (коридоры)


### 5.3. Что включено в результат (структура)
| Поле | Описание |
|---|---|
| Компания | Название (EN) + ссылка |
| Платформа | Alibaba / Made-in-China |
| Цена | min–max FOB |
| MOQ | диапазон/минимум |
| Локация | провинция/город |
| Стаж | годы на платформе |
| Метрики | рейтинг/response rate (если доступно) |
| Badges | Trade Assurance / Audited и др. |
| Индикатор риска | 🟢🟡🔴 + короткое объяснение |
| Проверка | кнопка → Продукт 1 (проверить поставщика) / Бандл |

### 5.4. Price/MOQ/Lead-time Benchmark — **новое**
Отдельный верхний блок результата:
- **Price corridor:** min / median / max по сопоставимым офферам
- **MOQ corridor:** типовые MOQ по рынку
- **Lead-time (если доступно из источников):** типовые сроки (индикативно)

> Это ключевой элемент, который делает продукт отличимым от “просто поиска на площадке”.

### 5.5. Риск-индикаторы — уточнение логики (чтобы не вводить в заблуждение)
Индикатор основан **только** на платформенных признаках и используется как triage:
- 🟢 “похоже на зрелого поставщика по признакам площадки”
- 🟡 “нужно уточнить ключевые вопросы”
- 🔴 “высокий риск шумного/нового профиля на площадке”

**Обязательная подпись:** “Не заменяет проверку QCC/Tendata”.

### 5.6. Кнопка "Сформировать запрос"
- бот формирует запрос коммерческого предложения (rfq) с указанием товара и характеристик по нажатию. Юзер может скопировать и отправить по email, wechat, алибаба/mic.

### 5.6. Формат выдачи
**Интерактивный веб-отчёт:**
- сортировка/фильтры
- экспорт в Excel и пдф 
- кнопки апсейла на проверку

### 5.7. Цена и экономика
- Цена: **$10**
- Себестоимость (Apify): **$4–5**
- Маржа: **50–60%**
- Стратегия: продукт — вход в апсейл на 1–2 (и частично на 4)

### 5.8. Источник данных
**Apify scrapers** для Alibaba и Made-in-China.

## 6) Продукт 4: Анализ рынка поставок (KZ) + Actionable Insights

### 6.1. Суть продукта
Отчёт о реальных поставках товара (HS-код) из Китая в Казахстан за последние 12 месяцев:  
**кто реально экспортировал, в каких объёмах, с какими диапазонами цен**.

### 6.2. Ключевая ценность
Пользователь видит **реальных экспортёров по Казахстану** и может:
- быстрее собрать shortlist “тех, кто уже возит в КЗ”;
- оценить рыночные диапазоны;
- понять структуру конкуренции и сезонность.

### 6.3. Входные данные
- Категория / описание товара (через AI-диалог)
- HS-код (4–8 цифр)
- Период (по умолчанию 12 месяцев)

### 6.4. Что включено в отчёт (данные)
| Раздел | Данные |
|---|---|
| Обзор рынка | общий объём импорта в КЗ по HS |
| Топ экспортёров | список китайских компаний (без раскрытия импортёров) |
| Объёмы по поставщику | вес/стоимость/кол-во (где доступно) |
| Ценовой диапазон | min–max–avg |
| Динамика | по месяцам |
| Сезонность | пики |
| Действие | “Проверить” → Продукт 1/2 |

### 6.5. Actionable Insights — **новое**
Добавляется финальный блок “Выводы для закупки”:
- **Концентрация рынка:** 2–3 игрока доминируют или рынок фрагментирован
- **Стабильность потока:** ровный импорт или сезонные пики
- **Ценовой ориентир:** “где находится медиана” + подозрительные выбросы
- **Рекомендованный следующий шаг:**  
  - “выберите 3–5 экспортёров из топа → проверьте по бандлу 1+2”

### 6.6. Конфиденциальность
Импортёры (казахстанские компании) **не раскрываются**. Отчёт показывает экспортёров и агрегаты.

### 6.7. Цена и экономика
- Цена: **$50**
- Себестоимость (Tendata): **$10–15**
- Маржа: **70–80%**

### 6.8. Источник данных
**Tendata API**: `catalog=imports`, `destinationCountryCode=KAZ`, фильтр HS и периода.

## 7) Единый Supplier ID и “сшивка” продуктов (критично для качества и data-layer)

Чтобы линейка работала как система, вводится логика “Supplier ID”:

- Для QCC: USCC → **canonical id**
- Для Tendata: match к компании → привязка к canonical id
- Для Apify: ссылки на профили → вероятностный матч + подтверждение

**Результат:** пользователь видит одного и того же поставщика во всех продуктах, отчёты “сцепляются”, повышается доверие и снижается стоимость повторных проверок.

## 8) Data-layer и кеширование (как накапливаем актив без юридических рисков)

### 8.1. Что сохраняем
- агрегаты и признаки (features), например:
  - факт экспорта (да/нет), страны, HS-направления, регулярность
  - тип компании, статус, возраст, базовые рисковые признаки
  - платформенные метрики (годы, бейджи, рейтинги)

### 8.2. Что НЕ сохраняем как “переиспользуемые сырые данные”
- построчные trade-записи “как есть” (если лицензионно/юридически нежелательно)
- любые поля, которые могут восприниматься как перепродажа данных

### 8.3. Зачем это нужно продуктово
- ускорение отчётов
- снижение себестоимости
- повышение качества ранжирования в продукте 3
- основа для будущих подписочных функций (мониторинг)

## 12) Дисклеймеры (актуализированы)

### Продукт 1
Отчёт составлен на основе данных из открытых государственных источников КНР. TradeLab не несёт ответственности за полноту и актуальность данных в первоисточнике. Отчёт носит информационный характер и не является юридическим заключением.

### Продукт 2
Данные об экспортной активности получены из международных таможенных баз данных и могут иметь задержку 1–3 месяца. Объёмы являются оценочными. Блок “Релевантность к сделке” — аналитическая интерпретация признаков, а не гарантия результатов сотрудничества.

### Продукт 3
Результаты поиска и риск-индикаторы основаны на публичных данных торговых платформ и предназначены для предварительного отбора кандидатов. Для принятия решения рекомендуется использовать проверку по продуктам 1–2.

### Продукт 4
Отчёт содержит агрегированные данные о поставках из Китая в Казахстан; информация об импортёрах не раскрывается. Данные могут быть неполными для отдельных категорий.
